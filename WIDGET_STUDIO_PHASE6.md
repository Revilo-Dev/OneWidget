# Widget Studio Phase 6

Phase 6 migrates the active Digital Clock configuration preview to shared
`RemoteViews` rendering and registers Battery as the second complete Widget Studio
widget. Studio designs remain developer-only.

## Configuration preview

`widget_provider_digital_clock.xml` points to `WidgetConfigActivity`, so that is the
active Digital Clock configuration screen. `DigitalClockConfigActivity` is retained
as unused legacy code and was not expanded.

`RemoteViewsPreviewHost` now owns the reusable `RemoteViews.apply()` failure boundary.
Widget Studio's `ActualRemoteViewsPreview` is a compatibility subclass of that host,
and `WidgetConfigActivity` uses the host for Clock and Battery. Other configuration
previews remain on the legacy local path.

Clock preview input is produced from the current in-memory controls by
`ClockConfigPreviewMapper`; it is never saved to `widget_prefs` for previewing.
`ClockRenderMode.CONFIG_PREVIEW` selects the same production layout as
`PRODUCTION`, supplies `design = null`, and omits external click actions. If local
`RemoteViews.apply()` fails, diagnostics are logged and the former local preview is
used as a deprecated fallback.

The preview is local app rendering. Native One UI blur remains launcher-only.

## Battery production flow mapped before extraction

- Provider entry points: `onUpdate`, options changes, scheduled refresh, battery,
  power, and Bluetooth connection broadcasts.
- Size rule: compact when minimum height is at most 100dp or minimum width is below
  250dp; otherwise large.
- Compact layout: selected device percentage, charging/device icon, and a composite
  bitmap progress track/fill.
- Large layout: up to four connected devices, each with icon, label/percentage, and
  the same composite progress bitmap.
- Runtime data: phone percentage/charging plus connected Bluetooth battery levels;
  power-saving state affects progress colour.
- Appearance: existing per-widget text, alignment, scale, tint, state colours, and
  global gradient setting.
- Progress: `WidgetProgressBarRenderer`.
- Tap actions: none existed and none were added.
- Blur: both production layouts retain `@android:id/background` and
  `widget_clock_background`.

## Shared Battery renderer

`BatteryWidget` now adapts existing preferences and runtime device data, calls
`BatteryRemoteViewsRenderer`, and always supplies `design = null`. Its update,
refresh, preference, provider, and layout thresholds are unchanged.

`BatteryRemoteViewsRenderer` chooses the original compact/large layout for production
and configuration preview. A design selects `widget_studio_battery`, whose root keeps
the same blur-compatible structure. Runtime data and configuration are independent of
`WidgetDesignSpec`.

Studio, Developer Test Widget, and snapshot modes use deterministic 72% / Charging
sample data. The existing generic registry, developer-host resolver, snapshot
renderer, repository, and gallery resolver require no Battery-specific branching.

## Studio design and geometry

Battery has four stable elements:

- `battery.percentage`
- `battery.status`
- `battery.icon`
- `battery.progress`

The current production progress representation is one bitmap containing both track
and fill, so it is exposed as one honest Studio element rather than two fictional
runtime views. Percentage and status expose text alignment; the icon does not.
Progress alone exposes `CORNER_RADIUS`.

All 1x1–5x5 variants are supported. The base design uses sparse compact overrides for
1x1/2x1 and sparse larger overrides for 2x2/4x2/5x5; other variants inherit.

`RemoteViewsGeometryCompat` centrally guards API 31 size, position, and preferred
outline-radius calls. Below API 31 the XML shape/radius remains in use and diagnostics
report ignored dynamic geometry. The progress bitmap continues to be generated by
`WidgetProgressBarRenderer`.

The EDIT canvas uses descriptor-provided visual types/sample data rather than widget
ID conditionals. Battery therefore draws representative text, icon, and progress
content through the same generic canvas.

## Production isolation

- Digital Clock production still calls its renderer with `design = null`.
- Battery production calls its renderer with `design = null`.
- Neither production provider loads `WidgetDesignRepository`.
- Samsung native blur code and root contracts were not changed.
- Weather, Storage, Calendar, Toggle, Media, Search, and lock-screen widgets were not
  onboarded.
